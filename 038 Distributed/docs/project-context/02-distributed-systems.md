# Distributed systems (микрогриды)

## Определение и ключевая семантика

Distributed system = изолированная микросеть (микрогрид) на площадке: одна общая шина, к которой параллельно подключаются генераторы и BESS через paralleling panel.

**Islanded ≠ Open — критическое различие:**
- **Islanded** — шина запитана, система питает нагрузку независимо. Для off-grid флота это **постоянное свойство**, не транзиторное состояние.
- **Open** — шина обесточена, ничего не питается.

## Связь с Paralleling panel (важное разъяснение)

**Панель — необходимое условие здоровья системы, но не достаточное.** Связь асимметричная:
- Отказ панели ⇒ отказ системы (шина падает целиком)
- Здоровье панели (щит физически исправен) ⇏ здоровье системы

Панель не видит:
- **Почему** разомкнут конкретный источник (штатный standby / не запустился / забыли перевести в Auto) — причина живёт в таблицах генераторов/BESS
- **Запас энергии** — SoC батарей панели вообще не известен
- **Деградацию, которая ещё не проявилась** — генераторы на грани ТО, BESS с низким SoH — панель показывает норму по шине
- **Потребителей** — например, зарядку с деградировавшими модулями, которая просто берёт меньше с шины (для панели выглядит как улучшение)

Отсюда разделение метрик:

| Метрика | Где живёт |
|---|---|
| Bus V/Hz, Load %, N-1 резерв, Sources closed, Energy reserve | **Distributed system** (операционный дашборд) |
| Control Auto/Manual, Breaker wear, Max contact temp, Service in, срабатывания защит | **Panel** (hardware-реестр) |

## Ключевые метрики таблицы Distributed systems

**Bus (V · Hz)** — измеряется панелью, характеризует систему. Частота на изолированной шине — метрика баланса мощности в реальном времени: не хватает генерации → частота проседает. Пример из обсуждения: 59.4 Гц при нагрузке 72% при формально "Operational" статусе — ранний сигнал, что регулятор одного из источников не справляется.

**Power load, %** — с обязательной **засечкой N-1** на баре. N-1 = уровень, при превышении которого отказ крупнейшего замкнутого источника вызовет перегрузку остальных. Динамическая величина — засечка сдвигается при каждом (от)ключении источника, даже если нагрузка не меняется. Два случая с одинаковым % нагрузки, но разным числом замкнутых источников, несут разный риск — без засечки это неразличимо.

**Sources closed (N of M)** — сколько выключателей замкнуто из общего числа источников системы (генераторы + BESS вместе).

**Energy reserve** — суммарный SoC батарей системы, единственная метрика, которую панель принципиально не видит. Решает вопрос автономности площадки.

**Curtailment (concept, not yet a column)** — высокая загрузка генераторов сама по себе не тревожна (DS180 динамически регулирует ставку заряда). Тревожен обратный случай: зарядка ограничена, при этом доступная генерация не выбрана полностью — сигнал сбоя power management, не подхватившегося источника или проблемы панели.

## Метрики, которые нельзя оценить по одному генератору/BESS — только на уровне системы

- **N-1 резерв** — свойство совокупности источников
- **Разброс наработки по группе** (max − min моточасов) — если ротация запусков сломана, часть парка выходит на ТО раньше остальных
- **Реактивная балансировка (kVAr sharing)** — ловит проблемы AVR/возбуждения отдельно от активной мощности

## Открытые вопросы

- 1:1 с панелью → нужно решить: схлопывать разделы Panels и Distributed systems в интерфейсе, или держать раздельно (первый — операционный дашборд, второй — hardware-реестр)
- Наименование "Distributed system" vs "Micro grid" встречается непоследовательно в разных карточках — нужна унификация терминологии и префикса ID
- Где физически исполняется dispatch strategy BESS и load-dependent start/stop генераторов — вероятно на уровне системы/EMS, не отдельного ассета (см. файлы Gensets, BESS)
